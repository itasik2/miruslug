# Локальный запуск «Мир Услуг»

Этот каталог поднимает архивную версию сайта «Мир Услуг» в изолированном Docker-окружении без изменения оригинальных файлов сайта.

## Что запускается

- Apache + PHP 5.6
- MODX Evolution 1.0.15 из `sources/miruslug`
- MySQL 5.7
- автоматический импорт `sources/itasi178_servdb.sql`

Веб-сервис привязан только к `127.0.0.1`, поэтому по умолчанию он недоступен из внешней сети.

## Требования

Нужен один из вариантов:

- Docker Engine + Docker Compose v2;
- Podman + `podman compose`;
- Podman + `podman-compose`.

## Запуск

Из корня репозитория:

```bash
cd legacy-docker
docker compose up -d --build
```

Для Podman используйте эквивалентную команду `podman compose up -d --build`.

Первый запуск может занять несколько минут: MySQL создаёт базу и импортирует старый SQL-дамп.

Проверить состояние:

```bash
docker compose ps
docker compose logs -f web
```

Сайт:

```text
http://localhost:8080
```

Старая панель MODX:

```text
http://localhost:8080/manager/
```

## Восстановление доступа в MODX Manager

В архивном дампе есть старая учётная запись администратора, но её старый пароль не требуется и не должен использоваться. Для локальной копии можно безопасно назначить новый пароль и одновременно снять блокировку после неудачных попыток входа.

Из каталога `legacy-docker` выполните:

```bash
bash bin/reset-admin.sh admin
```

Скрипт интерактивно попросит новый пароль, не сохраняет его в репозитории, сбрасывает `blocked`, `blockeduntil`, `blockedafter` и `failedlogincount`, а затем показывает итоговое состояние учётной записи.

После этого откройте:

```text
http://localhost:8080/manager/
```

и войдите под пользователем `admin` с только что заданным паролем.

Скрипт временно записывает совместимый с MODX legacy-MD5 хеш. При первом успешном входе штатный код MODX автоматически преобразует пароль в настроенный формат менеджера.

## Проверка старой админки и бизнес-части

После восстановления входа запустите:

```bash
bash bin/inspect-admin.sh
```

Проверка выводит без паролей:

- состояние контейнеров;
- manager-пользователей и блокировки;
- установленные модули MODX;
- города из `srv_manager_CITY_INFO`;
- наличие `eForm`, `city_info`, `Ditto` и form chunks;
- количество документов в старом сайте.

В исходном дампе уже есть отдельный MODX-модуль `Города`, таблица `srv_manager_CITY_INFO` и формы заявок на базе `eForm`. Поэтому после восстановления Manager следующий этап — проверить именно эти старые функции через интерфейс и исправлять только то, что реально сломано.

## Остановка

```bash
docker compose down
```

## Полный сброс базы и повторный импорт

```bash
docker compose down -v
docker compose up -d --build
```

Важно: `down -v` удалит локальный Docker volume базы. Исходный SQL-файл в репозитории не изменяется. После полного сброса базы пароль администратора также вернётся к архивному состоянию, поэтому снова выполните `bash bin/reset-admin.sh admin`.

## Если сайт показывает ошибку

Посмотреть логи:

```bash
docker compose logs --tail=200 web
docker compose logs --tail=200 db
```

Проверить, что MySQL готов:

```bash
docker compose ps
```

Для старого MODX используются расширения PHP `mysql`, `mysqli` и `pdo_mysql`, а Apache запускается с `mod_rewrite` и `AllowOverride All`, поскольку оригинальный `.htaccess` использует Friendly URLs.

## Безопасность

Это архивное приложение 2015 года на неподдерживаемом стеке. Не публикуйте контейнер напрямую в интернет. Конфигурация специально использует привязку:

```text
127.0.0.1:8080:80
```

Для публичной демонстрации сначала ставьте перед ним современный reverse proxy и ограничение доступа.
